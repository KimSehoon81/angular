# CareFlow Lite — 공단 제출 프로그램 연계 PRD

- 문서 버전: 0.1 (초안) · 작성일: 2026-10-23
- 상태: 설계만 해당. 개발은 시작하지 않는다.
- 한 줄 요약: **CareFlow는 공단 제출·보고용 프로그램(요양사랑 등)을 대체하지 않고 옆에서 돕는다.** 제출 전에는 빠짐없이 점검하고, 제출 후에는 결과를 대조하며, 월 마감 업무를 놓치지 않게 한다.

## 1. 현황 — 확인된 것과 확인 안 된 것

| 구분 | 내용 | 확인 상태 |
|---|---|---|
| "요양사랑"이 무엇인지 | 제조사, 기능, 공단 제출 방식, 데이터 입출력 기능을 공개 자료에서 **찾지 못했다**. 같은 계열로 보이는 상용 프로그램 '케어포'(한강시스템)는 존재하나 요양사랑과 같은 제품인지 확인되지 않았다 | **미확인 — 운영자 자료 필요** |
| 청구 방식 | 장기요양기관은 급여비용 청구서류를 **전자문서교환방식 또는 전산매체**로 공단에 제출한다 ([청구 및 심사·지급업무 처리기준](https://www.nhis.or.kr/lm/lmxsrv/law/lawFullContent.do?SEQ=101)) | 검색 요약 기준, **원문 확인 필요** |
| 청구서 외 제출 서류 | 관리현황 통보서, 종사자 근무현황 통보서, 인건비 지출내역서 등이 기관 유형별로 있다는 요약이 있었다 | **기관 유형별 정확한 목록 미확인** |
| 청구방법 변경 | 청구방법을 바꾸려면 사전에 청구방법 신청(변경)서를 공단에 제출 | 검색 요약 기준, 원문 확인 필요 |
| 급여제공기록 전송 | 재가급여전자관리시스템으로 전송하면 기록지 제공 주기가 월 1회 이상으로 완화 ([고시](https://www.nhis.or.kr/lm/lmxsrv/law/lawFullContent.do?SEQ=1637)) | 검색 요약 기준, 최신 개정본 확인 필요 |
| 계약 통보 | 계약 체결·변경 시 급여계약통보서를 공단에 통보 | 검색 요약 기준, 통보 기한·대상 **미확인** |
| 청구 시기·일정 | 급여 제공일이 속한 다음 달 초부터 월별 청구한다는 안내 블로그가 있으나 비공식 자료 | **미확인 — 공단 공식 안내 확인 필요** |
| 제출 프로그램이 파일 가져오기/내보내기를 지원하는지 | 모름 | **미확인** |

**따라서 지금 설계가 확정할 수 있는 것은 "구조"까지**다. 프로그램별 파일 형식, 화면 순서, 제출 서류 목록은 운영자가 제공하는 매뉴얼·화면·샘플 파일을 보고 §8의 절차로 확정한다. 이 문서는 그 전까지 추측으로 항목을 만들지 않는다.

## 2. "사용법을 알아야 한다"는 말의 의미

연계를 설계하려면 제출 프로그램의 **업무 순서와 입출력**을 알아야 한다. 인터넷에서 얻을 수 있는 정보로는 한계가 있고(§1), 센터가 실제 쓰는 버전·설정은 운영자만 안다. 그래서 다음을 받아 `제출 업무 맵`(§8)을 만든다.

## 3. 역할 분담

| 업무 | 제출 프로그램 / 공단 포털 | CareFlow |
|---|---|---|
| 공식 청구서 작성·제출 | **담당** (사람이 수행) | 하지 않음. 제출 자동화·화면 조작 금지 |
| 급여제공기록 공단 전송 | **담당** (현재 방식 유지, [Q-BIZ-12](OPEN_QUESTIONS.md)) | 가져와 대조 |
| 일정 관리·직원 배정 | 약함/없음(미확인) | **담당** |
| 요양보호사 기록 입력 | 프로그램에 따라 다름 | [DATA_ENTRY](DATA_ENTRY.md) 방식으로 입력 부담 축소 |
| 제출 전 점검(누락·불일치·필수 항목) | 일부(미확인) | **담당**: 일정↔기록↔태그↔제출 파일 대조 |
| 상태변화기록·계획서 초안 | 미확인 | **담당** |
| 본인부담금 정산 안내 | 미확인 | **담당** (규칙 확인 전 held) |
| 제출 후 결과 대조·수납 | 결과 제공 | **담당**: 제출액·결과·수납 차이 |
| 마감일·통보 업무 알림 | 약함/없음(미확인) | **담당** |
| 자격증·서류 만료 관리 | 미확인 | **담당** |

원칙: **제출 프로그램의 데이터가 공식 제출본이다.** CareFlow는 제출본을 바꾸지 않고, 차이가 나면 알려 준다.

## 4. 목표와 성공 지표

| 목표 | 지표(안, 기준값은 첫 달 측정) |
|---|---|
| 제출 후 반려·정정 감소 | 반려/조정 건수 |
| 월 마감 점검 시간 감소 | 마감 주간 총 소요 시간 |
| 이중 입력 제거 | 같은 정보를 두 번 입력하는 항목 수 |
| 마감·통보 누락 0 | 기한 초과 건수 |
| 제출 후 차이 즉시 발견 | 청구액↔결과↔수납 차이 발견까지 일수 |

## 5. 연계 방식과 권장안

| 방식 | 설명 | 장점 | 의존·위험 |
|---|---|---|---|
| **A. 동반(읽기) 방식** | 기록은 지금처럼 제출 프로그램/공단 앱에 입력. CareFlow는 내려받은 파일을 가져와 점검·알림 | 제출 프로그램을 건드리지 않음, 즉시 시작 가능 | 내려받기 가능한 데이터 범위에 의존. 일정·상태관찰 등은 CareFlow에서 별도 입력 |
| **B. 원본 전환 방식** | 기록을 CareFlow에 한 번 입력하고, 제출 프로그램으로 가져오기(import) | 이중 입력 최소 | 제출 프로그램이 가져오기를 지원하고 형식이 문서화·검증되어야 함. 형식 변경 위험 |
| **C. 병행 방식** | 공단 필수 항목은 제출 프로그램, 부가 항목(일정, 상태관찰, 주간기록, 문서)은 CareFlow. 서로 대조 | 위험 낮음 | 일부 이중 입력 남음 |

**권장**: A 또는 C로 시작한다 → 파일 형식과 제출 프로그램의 가져오기 기능이 확인되면 B를 단계적으로 검토한다. 이유: B는 제출 프로그램의 비공개·변경 가능 형식에 의존하고, 잘못된 파일이 곧 공식 제출 오류가 되기 때문이다.

## 6. 월 업무 사이클 (제출 달력)

각 단계의 날짜·기한은 **설정값**이다. 공식 기한이 확인되면 근거(출처·확인일)와 함께 등록하고, 확인 전에는 센터 내부 목표일로만 표시한다.

| 단계 | 내용 | CareFlow 기능 |
|---|---|---|
| 1. 방문·기록 (상시) | 방문 → 기록 입력 | 입력 대기 목록, 입력 지연 경고 |
| 2. 주간 점검 (매주) | 기록 누락·태그 불일치 해소 | Daily Ops, 태그 대사 |
| 3. 월 마감 준비 (월말 D-n) | 미해결 건 정리, 자격·서류 확인 | 마감 체크리스트, Claim Validation |
| 4. 제출 전 점검 (제출 직전) | 최종 점검 리포트 | **FR-INT-05** |
| 5. 제출 (사람) | 제출 프로그램에서 청구 작성·제출 | 제출 기록 입력 (FR-INT-06) |
| 6. 결과 확인 (제출 후) | 심사·지급 결과 대조 | **FR-INT-07, 08** |
| 7. 정산·안내 | 본인부담금 안내, 수납 | Billing Agent, 수납 기록 |
| 상시 통보 업무 | 계약 체결·변경, 기관정보·종사자 변경 | **FR-INT-11** |

## 8. 제출 프로그램 파악 절차 ("사용법 학습")

### 8.1 운영자께 받을 자료

1. 프로그램 이름·제조사·버전, 사용 중인 메뉴/모듈 (요양사랑 외에 공단 포털·재가급여전자관리시스템도 쓰는지)
2. 사용 설명서(PDF/웹), 없으면 **화면 캡처**(개인정보 가린 것)
3. 월 마감 업무를 실제로 하는 순서 — 어떤 메뉴를 어떤 순서로 누르는지 (녹화 화면 가능)
4. **내려받기/내보내기** 가능한 파일 목록과 **샘플 파일**(수급자·직원 이름·번호는 임의 값으로 바꾼 것)
5. **가져오기/업로드** 기능 여부와 그 양식 (엑셀 템플릿 등)
6. 최근 3개월 반려·조정 사례(어떤 오류였는지, 개인정보 제외)
7. 제출 일정(언제 무엇을 제출하는지 센터에서 지키는 달력)

### 8.2 우리가 만드는 산출물

| 산출물 | 내용 |
|---|---|
| 제출 업무 맵 | 업무별: 제출 프로그램의 메뉴 → 필요한 데이터 → 데이터가 CareFlow의 어디에 있는지 → 자동화 가능 정도(점검/알림/가져오기/내보내기/불가) |
| 프로그램 프로필 | 가져오기·내보내기 열 매핑, 인코딩, 필수 열, 샘플 파일 해시, 확인일 |
| 대조 규칙 | 제출 프로그램 데이터와 CareFlow 데이터를 비교하는 규칙(§9) |

| # | 업무 | 제출 프로그램 메뉴 | 기한 | 필요 데이터 | CareFlow 지원 | 근거·확인 |
|---|---|---|---|---|---|---|
| 1 | 월 급여비용 청구 | ? | ? | 제공 내역 | 사전 점검, 대조 | 미확인 |
| 2 | 급여제공기록 전송 | ? | ? | 기록지 | 가져와 대조 | 미확인 |
| 3 | 급여계약 통보(체결·변경) | ? | ? | 계약 정보 | 이벤트 감지→업무 | 미확인 |
| 4 | 종사자 근무현황 등 통보 | ? | ? | 직원·근무 | 집계 제공 | 미확인 (서류 종류 확인 필요) |
| 5 | 기관정보 변경 통보 | ? | ? | 기관 정보 | 알림 | 미확인 |

`?`는 모른다는 뜻이다. 추측으로 채우지 않는다.

## 9. 대조·점검 규칙 (후보, 모두 operational/integrity)

| 규칙 | 내용 |
|---|---|
| `INT.RECORD_MISSING_IN_PROGRAM` | CareFlow에는 방문 기록이 있으나 제출 프로그램 파일에 없음 |
| `INT.RECORD_MISSING_IN_CAREFLOW` | 제출 프로그램 파일에는 있으나 CareFlow 일정·기록에 없음 |
| `INT.TIME_MISMATCH` | 같은 방문의 시각이 두 곳에서 다름 (허용 오차는 설정값) |
| `INT.COUNT_SUM_MISMATCH` | 수급자·월 단위 방문 횟수/시간 합계 불일치 |
| `INT.AMOUNT_MISMATCH` | 제출액(프로그램) ↔ CareFlow 계산(검증된 규칙이 있을 때만) ↔ 결과 금액 차이 |
| `INT.MAPPING_FAILED` | 수급자·직원 식별 불가 |
| `INT.PROFILE_DRIFT` | 파일 구조가 프로필과 다름 → 가져오기 중단 |
| `SUBMIT.PREFLIGHT_OPEN_ERRORS` | 제출 전 미해결 오류 존재 |
| `SUBMIT.CYCLE_DUE` | 제출 업무 기한 임박/초과 (기한은 설정값) |

공식 청구 요건에 대한 검증은 [RULE_ENGINE_SPEC](RULE_ENGINE_SPEC.md)의 regulatory 규칙(공식 근거 확인 후 verified)만 판정에 쓴다.

## 10. 보안·금지

- 공단 시스템 **자동 로그인·화면 조작·스크래핑·인증서 대리 사용 금지.**
- **공동인증서, 공단 포털 계정·비밀번호를 CareFlow에 저장하지 않는다.**
- 제출 프로그램에서 내려받은 파일은 개인정보를 포함하므로 [SECURITY §5](SECURITY.md) 업로드 통제와 보관 정책을 적용한다 (원본 보관, 접근 권한, 보유 기간).
- 제출본으로 쓰인 파일은 수정 불가로 보관해 이후 대사의 기준으로 삼는다.
- 제출 프로그램 제조사의 이용약관(데이터 내보내기·연계 제한 여부)을 운영자가 확인한다 ([Q-INT-05](OPEN_QUESTIONS.md)).

## 11. 비목표

- 제출 프로그램의 기능 복제(공식 청구서 생성·전송)
- 공단 시스템 자동 제출·자동 조회
- 제출 프로그램 DB 직접 접근
- 공식 심사 결과 예측·보장

# CareFlow Lite — 기록 입력 전략 (옮겨 적기 최소화)

- 문서 버전: 0.1 (초안) · 작성일: 2026-10-23
- 배경: 종이 급여제공기록지를 사회복지사(사복)가 시스템에 옮겨 적는 방식이면 입력 업무가 사람에게 쌓인다. 이 문서는 **옮겨 적는 일 자체를 없애고, 남는 입력은 가장 빠르게** 하는 설계를 정한다.
- 상태: 설계만 해당. 개발은 시작하지 않는다.

## 1. 현황 파악 — 확인된 것과 확인 안 된 것

| 구분 | 내용 | 확인 상태 |
|---|---|---|
| 요양보호사가 방문 후 급여제공기록지를 작성한다 | 일반적인 업무 흐름 | 공개 자료에서 확인 ([쿠키뉴스](https://www.kukinews.com/article/view/kuk202506230135)) |
| 공단 모바일 앱과 전자태그로 기록지를 전송·관리하는 방식이 추진·운영되고 있다 | 앱 장애 시 수기 기록지로 대체하라는 공단 안내가 있었음. 기사 날짜 표기가 불일치해 **현재 상태는 미확인** | 부분 확인 |
| 앱 개편 후 서명 요건이 바뀌었다 (수급자·보호자 서명, 어려우면 사유서) | 기사 내용. 최신 규정은 **미확인** | 부분 확인 |
| 기록지를 재가급여전자관리시스템으로 전송하면 기록지 제공 주기가 월 1회 이상으로 완화된다 | 고시 제7조 ([장기요양급여 제공기준 및 급여비용 산정방법 등에 관한 고시](https://www.nhis.or.kr/lm/lmxsrv/law/lawFullContent.do?SEQ=1637)) | 검색 결과 기준, 최신 개정본 **원문 확인 필요** |
| 전자서명·스마트폰 기록의 인정 요건 | 이번 검색으로 확정하지 못함 | **미확인** |
| **사복이 종이 기록지를 옮겨 적는 것이 일반적인 방식인가** | 센터마다 다르다. 요양보호사가 앱·소프트웨어에 직접 입력하는 센터도, 종이를 모아 사무실이 입력하는 센터도 있을 것으로 보이나 **이를 뒷받침하는 통계나 공식 자료는 찾지 못했다** | **미확인 — 운영자 답변 필요** ([Q-BIZ-10, 12, 13](OPEN_QUESTIONS.md)) |

**설계에 중요한 시사점**: 공단 앱으로 이미 전송하고 있다면, CareFlow에 같은 내용을 또 입력하는 **이중 입력**이 가장 큰 낭비다. 이 경우 CareFlow는 입력 도구가 아니라 **공단 쪽 기록을 가져와 대조하는 도구**가 되어야 한다. 단, 공단 시스템을 자동 조작하는 방식은 금지이므로 사람이 내려받은 파일을 업로드하는 방식만 쓴다.

## 2. AI가 일일이 개입해야 하는가

종이를 사진·스캔해 AI가 읽게 하는 방식은 가능하지만 지금 범위와 충돌한다.

1. 기록지에는 수급자 건강 상태가 들어 있다. 사진을 외부 AI에 보내는 것은 이미 보류한 개인정보 전송 검토([Q-LEGAL-01](OPEN_QUESTIONS.md))와 같은 문제다. 이미지는 가명처리도 어렵다 (이름·인정번호가 손글씨로 들어 있음).
2. 한글 손글씨 인식은 정확도가 일정하지 않다. 틀린 값이 그대로 기록에 들어가면 청구 자료의 오류가 된다. 결국 사람이 전부 대조해야 한다.
3. 그래서 **AI 없이 옮겨 적는 양을 먼저 줄이고**, 그래도 남는 양이 많을 때 AI(또는 서버 내 OCR)를 검토한다 (§4 E5).

## 3. 입력 방식 단계 (효과가 큰 순서)

### E0. 이중 입력 제거 (가장 먼저 확인)

- 공단 앱·재가급여전자관리시스템에서 이미 기록을 전송하고 있다면, 그 기록을 사람이 내려받아 CareFlow에 업로드 → 매핑 → 불일치 검사. 재입력 없음.
- 필요한 것: 내려받을 수 있는 파일 형식과 항목 확인 ([Q-BIZ-01, 12](OPEN_QUESTIONS.md)).
- 이 경우 CareFlow가 직접 보관해야 하는 기록은 공단 파일에 없는 항목(상태 관찰 4개 항목, 주간 상태변화기록)으로 줄어든다.

### E1. 요양보호사 모바일 직접 입력 (옮겨 적기 제거)

종이를 거치지 않는다. 방문 직후 요양보호사가 휴대폰으로 입력한다.

| 설계 | 내용 | 줄이는 일 |
|---|---|---|
| 오늘 방문 목록 | 로그인하면 본인의 오늘 일정이 열린다. 수급자·시간은 일정에서 자동 채움 | 기본 정보 기입 |
| 체크 중심 화면 | 4개 서비스 영역은 큰 토글과 소요시간 버튼(10분 단위 가감), 세부 항목은 칩 선택. 상태 관찰 4개 항목은 선택형(정상/감소 등) | 손글씨 |
| 진행 저장 | 입력 중 자동 임시저장, 끊겨도 이어서 | 재입력 |
| 지난 방문 참조 | "지난 방문 값 불러오기"는 **제안**일 뿐이다. 항목마다 명시적으로 확인해야 저장된다. 일괄 자동 완료 금지 | 반복 입력 |
| 음성 입력 | 서술란은 휴대폰 기본 음성 입력(키보드 마이크)을 쓴다. 별도 AI 서비스 호출 없음 | 긴 서술 타이핑 |
| 상용구 | 센터가 등록한 자주 쓰는 문구를 한 번에 삽입 | 반복 타이핑 |
| 오프라인 | 방문 환경에서 통신이 약할 수 있으므로 입력 내용을 기기에 임시 보관했다가 연결되면 전송 (구현 방식은 [Q-BIZ-10](OPEN_QUESTIONS.md) 이후 결정) | 입력 실패 |

주의: 지난 방문 값을 그대로 복사해 반복하는 것은 기록의 신뢰성 문제가 될 수 있다. 시스템은 편의를 주되 **내용이 연속으로 동일하면 경고**(`REC.REPEATED_CONTENT`)한다. 허위·형식적 기록 여부를 판정하는 것이 아니라 확인 요청이다.

### E2. 종이를 유지할 때: 사전 인쇄 시트

요양보호사가 종이를 계속 써야 한다면(서명 수령, 통신 불가 등) 쓰는 양과 옮기는 양을 줄인다.

- 시스템이 **방문 일정에서 기록지를 사전 인쇄**한다. 수급자명·등급·기관기호·요양보호사·날짜·예정 시간이 이미 찍혀 있다.
- 기록 영역은 **체크박스와 숫자 칸 위주**로 재설계한다. 서술 칸은 "특이사항" 하나로 줄인다. ([FORMS §5](FORMS.md))
- 시트마다 **무작위 시트 코드(QR)**를 넣는다. 코드에는 개인정보를 넣지 않는다. 입력 화면에서 코드를 읽으면 해당 일정이 열린다.
- 인쇄 배치와 입력 화면 배치를 **동일하게** 한다. 눈이 움직이는 순서가 같아 입력이 빠르다.
- 한 달 치를 수급자별로 묶어 인쇄하면 방문마다 한 장씩 나가는 낭비를 줄일 수 있다 (한 장에 여러 방문 행 — 양식 허용 여부는 [Q-REG-12](OPEN_QUESTIONS.md)에서 확인).

### E3. 사복용 빠른 입력 화면

그래도 사무실에서 입력해야 하는 건을 위한 화면. 종이 기록지를 보며 키보드만으로 입력한다.

- **수급자 1명 × 1주 격자**: 행=방문일, 열=영역·관찰 항목. 방향키/Tab으로 이동, 숫자와 한 글자 코드(`Y/N`, `1/2/3`)로 입력.
- 시트 코드(QR 번호) 입력 → 일정·수급자·직원·시간 자동 채움. 사람이 입력하는 것은 체크 결과뿐.
- 저장 전 즉시 검사: 필수 항목 누락, 소요시간 합계 불일치, 일정에 없는 방문.
- **입력 대기 목록**: "방문은 했는데 기록이 아직 없는 건"을 날짜순으로 보여 주어 종이 더미와 대조하며 처리.
- 입력 시간 측정(건당) → 개선 효과 확인 ([§6](#6-성공-지표)).

### E4. 종이 원본 스캔 첨부 (증빙 보관)

- 서명이 들어간 종이 원본을 스캔·촬영해 기록에 **첨부 파일로 보관**한다. 읽어서 값을 채우지는 않는다.
- 파일은 웹 루트 밖에 저장하고 접근 권한을 통제한다 ([SECURITY §5a](SECURITY.md)).
- 보관 의무 기간과 원본 폐기 가능 여부는 확인 전까지 가정하지 않는다 ([Q-REG-12](OPEN_QUESTIONS.md)).

### E5. 사진·스캔 자동 읽기 (보류)

| 방식 | 장점 | 제약 |
|---|---|---|
| 외부 AI(LLM) 이미지 읽기 | 손글씨·서술 인식 | 개인정보 전송 검토 전까지 **사용 안 함** |
| 서버 내 OCR(오프라인) | 외부 전송 없음 | 한글 손글씨 정확도 낮을 수 있음, 서버 사양·설치 가능 여부 미확인 |
| **체크박스 판독(OMR)** — 사전 인쇄 시트 한정 | 외부 전송 없음, 결정론적, 체크 위치만 읽음 | 인쇄 정렬·스캔 품질에 민감. 판독 결과를 사람이 확인하는 화면 필수 |

E1~E3 적용 후에도 사무실 입력량이 많을 때 OMR을 먼저 검토하고, 그다음 AI를 검토한다. 어떤 방식이든 **읽은 값은 초안이며 사람이 확인한 뒤 저장**한다.

## 4. 선택 기준

| 상황 | 권장 조합 |
|---|---|
| 요양보호사가 공단 앱으로 이미 전송 중 | E0 + (공단 파일에 없는 관찰 항목만) E1 또는 E3 |
| 요양보호사가 스마트폰을 쓸 수 있고 서명도 전자로 가능 | E1 (종이 폐지에 가까움) |
| 종이 서명이 꼭 필요 | E2 + E3 + E4 |
| 요양보호사가 스마트폰을 쓰기 어려움 | E2 + E3 (사무실 입력을 가장 빠르게) |

어느 경우에도 **서명·원본 보관에 관한 법적 요건이 확인되기 전에는 종이를 없애지 않는다.** CareFlow는 종이와 전자 기록 둘 다 받을 수 있게 설계한다.

## 5. 입력 출처 추적

모든 서비스 기록에 입력 경로를 남겨 검증과 감사에 쓴다.

| `entry_source` | 의미 |
|---|---|
| `caregiver_mobile` | 요양보호사 직접 입력 |
| `staff_transcribed` | 사복이 종이를 보고 입력 |
| `official_import` | 공단 파일 가져오기 |
| `omr_confirmed` | (보류) 판독 후 사람이 확인 |

- `entered_by`, `entered_at`(입력 시각)과 `service_date`(방문일)의 차이를 규칙으로 점검한다 (`REC.ENTRY_LATE`: 방문 후 N일 경과 입력, N은 설정값. 법정 기한이 아님).
- 같은 방문에 출처가 다른 기록이 둘 이상이면 하나로 합치지 않고 불일치 경고를 만든다.

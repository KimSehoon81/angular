# 고양 통합재가방문센터 홈페이지 + 레트로 자가진단 계산기 PRD

| 항목 | 내용 |
|---|---|
| 문서 상태 | 초안 v0.1 (기획 단계, 개발 착수 전) |
| 작성일 | 2026-10-23 |
| 범위 | 센터 공식 홈페이지 + 홈페이지에 내장된 2D 레트로 자가진단·예상 비용 계산기 |
| 관련 문서 | 별도 프로젝트. CareFlow Lite(`docs/PRD.md`)와는 저장소·기술 스택이 다르며, 2단계 이후 상담 신청 데이터 연계만 검토한다(9장 Q-WEB-12). |

> **이 문서를 읽기 전에 꼭 알아둘 세 가지**
>
> 1. **한글 전용·소박한 홈페이지.** 화면에 보이는 모든 글자는 한글로 쓴다. 영어 메뉴명, 외래어 남발, 화려한 효과 없이 동네 센터답게 따뜻하고 단정하게 만든다.
> 2. **금액·등급 수치는 추측으로 채우지 않는다.** 수가·월 한도액·본인부담률은 `rates/2025.json` 한 곳에만 두고, 공단 고시 원문으로 확인한 값에 `verified: true`를 붙인 뒤에만 공개 화면에 쓴다. 이 문서의 수치 예시는 **검증 전 참고값**이다(5.5절).
> 3. **자가진단은 공단 판정이 아니다.** 공단 인정조사(52개 항목)를 12문항으로 흉내 낸 **참고용 추정**이다. 결과 화면마다 "정확한 등급은 국민건강보험공단 판정 결과에 따름" 문구를 붙인다.

# 1. Overview & Goals

## 1.1 한 줄 정의

일산서구 탄현·중산·덕이·고봉·성석동 어르신 가족이 **"우리 부모님도 받을 수 있을까, 얼마나 들까"** 를 3분 안에 알아보고, **간호사가 있는 동네 센터**에 바로 상담을 남길 수 있는 홈페이지.

## 1.2 배경

- 보호자는 장기요양 제도를 처음 접할 때 "등급이 뭔지, 신청은 어디서 하는지, 돈은 얼마인지"를 모른다. 공단 누리집은 정확하지만 어렵다.
- 동네 센터 홈페이지는 대개 소개 글 몇 장으로 끝나서, 블로그·검색으로 들어온 보호자가 다음 행동을 못 정하고 이탈한다.
- 우리 센터는 **방문간호 인력(간호사)을 직접 보유**하고 있어, 등급 판정 전후 간호가 급한 가정을 빠르게 연결할 수 있다. 이것을 처음 보는 사람도 바로 알게 해야 한다.

## 1.3 핵심 차별점(USP) 문구 원칙

| 구분 | 내용 |
|---|---|
| 핵심 메시지 | "우리 센터에는 **방문간호 간호사**가 함께 있습니다. 등급 결과를 기다리는 중에도 먼저 상담하고, 판정이 나오면 바로 시작할 수 있게 준비해 드립니다." |
| 노출 위치 | 모든 페이지 상단 띠 배너, 서비스 페이지 첫 화면, 자가진단 결과창, 모든 상담 버튼 옆 보조 문구 |
| 주의(법·사실 관계) | 장기요양 급여(공단 지원)는 **등급 판정 후**에만 적용된다. 등급 전 간호는 ① 상담·등급 신청 안내 ② 판정 즉시 시작을 위한 대기등록 ③ 센터가 제공 가능한 경우 전액 본인부담 비급여 안내로 한정해 표현한다. "등급 없어도 공단 지원으로 간호 가능" 같은 문구는 쓰지 않는다. 비급여 간호 제공 여부는 Q-WEB-03 확인 후 확정. |

## 1.4 목표

| 목표 | 지표 | 1차 목표값(오픈 후 3개월) |
|---|---|---|
| 보호자가 다음 행동을 정하게 한다 | 자가진단 완료율(시작 대비) | 60% 이상 |
| 상담 연결 | 자가진단 결과 → 상담 예약 버튼 클릭률 | 15% 이상 |
| 상담 접수 | 월 빠른 간호 상담·대기등록 접수 수 | 운영자와 오픈 전 합의(Q-WEB-10) |
| 지역 검색 노출 | "탄현동 방문요양", "일산서구 방문간호" 등 지역 키워드 검색 1페이지 노출 | 지정 키워드 10개 중 5개 |
| 쉬운 사용 | 60대 이상 사용성 시험 참가자의 상담 신청 완료 | 5명 중 4명 도움 없이 완료 |

## 1.5 범위

**포함**
- 센터 소개, 서비스 소개(방문요양·방문간호), 이용 절차·비용 안내, 오시는 길
- 레트로 자가진단·예상 비용 계산기(홈페이지 내장)
- 서비스 페이지 하단 일반형 간편 계산기
- 빠른 간호 상담·방문 예약(대기등록) 신청 폼과 완료 화면
- 재가방문센터 창업 상담 안내·문의
- 공지·자료실(제도 안내 글)

**제외 (100%)**
- 이동목욕 차량 관련 모든 것: 차량 소개 페이지, 차량 사진, 이동목욕 예약 기능, 차량 관련 문구
- 회원가입·로그인(보호자용)
- 온라인 결제
- 공단 누리집·장기요양 정보시스템 자동 접속·자동 신청
- 외부 AI(LLM) 상담 챗봇

**나중 확장 자리만 확보**
- `가정방문 목욕 안내` — 텍스트 안내 페이지 1장. 1차 오픈에서는 메뉴에 노출하지 않고 IA·코드에 주석으로 자리만 둔다(3장).

# 2. Target User & User Journey

## 2.1 페르소나

### P1. 등급 신청 전 보호자 — "김정희(54), 딸"

| 항목 | 내용 |
|---|---|
| 상황 | 덕이동에 혼자 사시는 어머니(81)가 최근 같은 말을 반복하고 약을 잘 못 챙긴다. 퇴근 후 휴대폰으로 블로그 글을 보다 들어왔다. |
| 아는 것 | "요양등급"이라는 말만 들어봄. 신청 방법·비용 모름. |
| 원하는 것 | 우리 엄마가 등급이 나올지, 나오면 무엇을 얼마에 받을 수 있는지 빨리 알고 싶다. |
| 불안 | 등급 나올 때까지 한 달 넘게 기다려야 한다는데 그동안 약·상처 관리가 걱정. |
| 기기 | 휴대폰(안드로이드), 글자 크기 크게 설정 |
| 성공 장면 | 자가진단 → "4~5등급 예상, 방문요양 + 방문간호 조합" 확인 → "빠른 간호 상담 예약"에서 "등급 신청 전" 선택 후 접수 → 다음 날 센터 전화 |

**여정**

```
블로그 글의 "3분 자가진단" 링크 클릭 (/?utm_source=blog#/check)
 → 자가진단 바로 시작(첫 화면 건너뜀)
 → 12문항 퀘스트 (약 3분)
 → 결과 보상창: 예상 등급·추천 서비스·월 예상 비용
 → "간호사와 빠른 상담 예약" 버튼 (현재 상태 '등급 신청 전'이 미리 선택됨)
 → 신청 폼 6칸 작성 → 대기등록 완료 화면(접수번호, 다음 할 일 안내)
 → (선택) "등급 신청은 이렇게 합니다" 안내 글 읽기
```

### P2. 등급 보유자 가족 — "박상철(62), 아들"

| 항목 | 내용 |
|---|---|
| 상황 | 중산동 아버지(84)가 3등급. 다른 센터 방문요양을 쓰는데, 욕창이 생겨 간호가 필요하다는 말을 들었다. |
| 아는 것 | 등급·본인부담금 개념은 안다. 방문간호는 잘 모름. |
| 원하는 것 | 방문간호 추가 시 한 달 비용이 얼마 더 드는지, 센터를 옮기거나 같이 쓸 수 있는지. |
| 기기 | PC 또는 태블릿 |
| 성공 장면 | 서비스 > 방문간호 페이지 → 하단 간편 계산기로 "요양 3시간 주 5회 + 간호 주 1회" 본인부담금 확인 → 빠른 상담 예약("등급 있음", 필요 서비스 "방문간호") |

### P3. 창업 문의자 — "이민수(47), 예비 창업자"

| 항목 | 내용 |
|---|---|
| 상황 | 요양보호사 자격이 있고 재가센터 창업을 고민 중. 검색하다 들어옴. |
| 원하는 것 | 인력 기준, 준비 절차, 상담 가능 여부. |
| 성공 장면 | 창업 상담 페이지 → 준비 절차 요약 읽기 → 창업 문의 폼(이름·연락처·희망 지역·문의 내용) 접수 |
| 주의 | 창업 페이지는 어르신 가족 동선과 분리한다(상단 메뉴 맨 끝). 수익 보장·"월 OO만 원" 같은 과장 표현 금지. |

## 2.2 공통 동선 원칙

- 어느 페이지에서든 **두 번 이내 누름**으로 상담 신청 폼에 도착한다.
- 휴대폰 하단 고정 바: `전화하기` · `빠른 간호 상담` (두 버튼만).
- 자가진단은 언제든 "그만하기"로 나갈 수 있고, 다시 들어오면 처음부터 시작한다(진행 상태를 서버에 저장하지 않음).

# 3. Information Architecture (IA) — Sitemap

## 3.1 사이트맵

```
고양 통합재가방문센터 (/)
├─ 센터 소개 (/about)
│   ├─ 인사말·운영 원칙
│   ├─ 함께하는 사람들 (간호사·사회복지사·요양보호사 직종별 소개, 실명·사진은 동의 시)
│   └─ 오시는 길·담당 지역 (/about/location)  — 탄현·중산·덕이·고봉·성석동
├─ 서비스 안내 (/services)
│   ├─ 방문요양 (/services/visiting-care)        + 하단 간편 계산기
│   ├─ 방문간호 (/services/visiting-nursing)     + 하단 간편 계산기  ★ USP 중심 페이지
│   └─ {/* 가정방문 목욕 안내 (/services/home-bath) — 텍스트 안내만. 1차 오픈 미노출, 자리만 확보 */}
├─ 3분 자가진단 (/check, 블로그 진입 /?utm_source=blog#/check)  ★ 킬러 콘텐츠
├─ 이용 안내 (/guide)
│   ├─ 장기요양 등급 신청 방법 (/guide/apply)
│   ├─ 이용 절차 (/guide/process)
│   └─ 비용·본인부담금 안내 (/guide/cost)
├─ 빠른 간호 상담 (/consult)  ★ 모든 상담 버튼의 도착지
│   └─ 접수 완료 (/consult/done)
├─ 소식·자료 (/news)
│   ├─ 센터 소식
│   └─ 제도 안내 글 (블로그 글 요약·원문 링크)
├─ 창업 상담 (/startup)
│   └─ 창업 문의 접수 완료 (/startup/done)
├─ 개인정보 처리방침 (/privacy)
└─ 이용약관·면책 안내 (/terms)
```

- URL 경로는 개발 편의상 영문 소문자로 두되, **화면에 보이는 메뉴명·제목·버튼은 전부 한글**이다.
- 상단 메뉴 순서: 센터 소개 · 서비스 안내 · **3분 자가진단** · 이용 안내 · 빠른 간호 상담(강조 버튼) · 소식·자료 · 창업 상담

## 3.2 명시적 제외

| 제외 항목 | 이유·처리 |
|---|---|
| 이동목욕 차량 소개 페이지 | 운영하지 않음. 페이지·메뉴·경로 생성 금지 |
| 이동목욕 차량 사진 | 이미지 자산에 포함 금지. 검수 체크리스트(8.5)에 포함 |
| 이동목욕 예약 기능 | 폼 선택지·계산기 선택지에도 넣지 않음 |
| 가정방문 목욕 안내 | **자리만**: IA·라우트 설정 파일에 주석으로 남김. 1차 오픈에서는 메뉴·사이트맵 XML·검색 노출 모두 없음 |

```ts

  { label: '방문요양', href: '/services/visiting-care' },
```

## 4.2 상세

### F-01 공통 레이아웃 (M)

- **User Story:** 보호자로서, 어느 페이지에 있든 센터 전화번호와 상담 버튼을 바로 찾고 싶다.
- **Acceptance Criteria**
  - [ ] 머리말: 센터 이름(글자 로고), 메뉴, "빠른 간호 상담" 강조 버튼.
  - [ ] 머리말 위 USP 띠: "간호사가 함께하는 재가센터 · 등급 결과 기다리는 중에도 먼저 상담하세요" (닫기 가능, 다음 방문 시 다시 표시).

### F-05 결과 보상창 (M)

# 5. Game Logic Detail

## 5.1 설계 원칙

- 공단 인정조사는 신체기능·인지기능·행동변화·간호처치·재활 영역 **52개 항목**과 통계 모형으로 **장기요양인정점수**를 낸다. 12문항으로 이를 재현할 수 없으므로, 이 계산은 **"인정점수와 비슷한 크기의 참고 점수"** 를 만드는 단순 가중합이다.
- 그래서 결과는 **등급 1개 + 앞뒤 범위**로 보여주고, 경계 근처면 범위를 넓힌다.
- 가중치·경계값은 코드에 흩어 두지 않고 `config/check-scoring.json` 한 파일에 둔다. 오픈 전 센터 간호사·사회복지사가 실제 판정 사례(익명, 합성 재현)로 보정한다(Q-WEB-05).

## 5.2 문진 항목 12개

- 플래그(점수와 별개로 결과 분기에 쓰임)
  - `F_DEMENTIA`: Q7에서 "치매 진단" 선택
  - `F_NURSING`: Q8 = 있음 또는 Q2 = 2
  - `F_COGNITIVE`: Q9 + Q10 + Q11 + Q12 원점수 합 ≥ 3
  - `F_UNDER65_NO_DISEASE`: 65세 미만 & Q7 = 없음

## 5.3 점수 계산

```
참고점수 = Σ (원점수ᵢ × 가중치ᵢ)            // 이론상 최대 = 2 × (5+3+5+4+6+6+4+4+3+3+3+2) = 96
보정점수 = round(참고점수 × 100 / 96, 1)      // 0~100 범위로 맞춤
```

신체 영역(Q1, Q3~Q6) 가중치 합이 26으로 가장 크게 잡힌 것은, 실제 인정점수에서 신체 도움 필요도가 가장 큰 비중을 차지한다는 일반적 이해를 반영한 **초기값**이다. 근거 자료가 아니므로 5.1절 보정 절차를 거친다.

## 5.4 등급 매핑

공단의 인정점수 구간(참고: 1등급 95점 이상, 2등급 75~95점 미만, 3등급 60~75점 미만, 4등급 51~60점 미만, 5등급 45~51점 미만 + 치매, 인지지원등급 45점 미만 + 치매)을 **틀로만** 빌려 쓴다. 구간값도 `config/check-scoring.json`에 두고, 공단 고시로 확인해 `verified` 표시한다.

```ts
function estimateGrade(score: number, f: Flags): GradeResult {
  if (f.F_UNDER65_NO_DISEASE) return { grade: 'NONE', note: '65세 미만은 노인성 질환이 있어야 신청 가능' };
  if (score >= T.g1)                 return { grade: 1 };
  if (score >= T.g2)                 return { grade: 2 };
  if (score >= T.g3)                 return { grade: 3 };
  if (score >= T.g4)                 return { grade: 4 };
  if (score >= T.g5 && f.F_DEMENTIA) return { grade: 5 };
  if (score >= T.g5 && !f.F_DEMENTIA)return { grade: 'NONE_OR_5', note: '치매 진단을 받으셨다면 5등급 가능성' };
  if (f.F_DEMENTIA)                  return { grade: 'COGNITIVE' };   // 인지지원등급
  if (f.F_COGNITIVE)                 return { grade: 'NONE', note: '기억력 변화가 보여요. 치매 검사 후 다시 확인해 보세요' };
  return { grade: 'NONE' };
}
// T = { g1: 95, g2: 75, g3: 60, g4: 51, g5: 45 }  ← config에서 읽음
```

**범위 표시 규칙**

- 경계값과의 차이가 5점 이내면 이웃 등급을 범위에 포함. 예: 보정점수 62 → "3등급 예상 (3~4등급 사이)".
- 그 밖에는 ±1등급을 기본 범위로 표시하지 않고 "OO등급 예상"만 표시하되, 공통 문구로 실제와 다를 수 있음을 알린다.
- `NONE_OR_5`는 "등급 외 또는 5등급"으로 보여준다.

### 계산식 (`lib/cost.ts`, 순수 함수, 정수 원 단위)

```
방문요양 1회 수가     = visitingCare 표에서 (1회 시간 ≥ minMinutes)인 가장 큰 구간의 fee
방문요양 월 비용      = 방문요양 1회 수가 × 월 방문 횟수
방문간호 월 비용      = visitingNursing[band].fee × 월 방문 횟수
월 총 급여비용        = 방문요양 월 비용 + 방문간호 월 비용

한도 내 금액          = min(월 총 급여비용, monthlyLimit[등급])
한도 초과 금액        = max(0, 월 총 급여비용 − monthlyLimit[등급])

본인부담금(구분별)    = floor(한도 내 금액 × copayRate[구분] / 10) × 10   ← 끝전 처리 방식은 Q-WEB-07에서 확인 후 확정
공단 부담금           = 한도 내 금액 − 본인부담금
실제 내실 돈          = 본인부담금 + 한도 초과 금액
```

**계산 예시 (구조 설명용, 숫자는 가상값)**

> 방문요양 1시간당 `A`원(가상: 25,000원), 3등급 월 한도 `L`원(가상: 1,500,000원)이라고 할 때
> 하루 1시간 × 월 20일 = 25,000 × 20 = 500,000원
> 본인부담금: 일반 15% = 75,000원 / 감경 9% = 45,000원 / 감경 6% = 30,000원 / 기초수급 0원
>
> ※ 위 25,000원·1,500,000원은 **실제 수가가 아닌 설명용 가상값**이다. 화면·코드·테스트 기대값에 실제 값처럼 쓰지 않는다.

### 계산 규칙

- 모든 금액은 정수(원). 부동소수점 곱셈 후 반올림 대신 정수 연산(`Math.floor(amount * rateBp / 10000)` 형태, 비율은 만분율 정수로 저장)으로 한다.
- 계산은 브라우저에서 해도 되지만 **같은 모듈을 서버 테스트에서도 실행**해 결과를 고정한다.
- 화면 표시는 천 단위 쉼표 + "원". "약 OO원" 표현과 "평일 낮 기준 예시" 문구를 함께 쓴다.

**파일 구조**

| `spr-ui-icon-nurse` | 간호사 모자 아이콘(방문간호) |

## 7.4 블로그 딥링크 구조

```
블로그 링크 ① https://<도메인>/?utm_source=blog&utm_campaign=<글번호>#/check
블로그 링크 ② https://<도메인>/check?utm_source=blog&utm_campaign=<글번호>   (권장, 공유 미리보기 정상)
```

처리 순서(첫 화면 `page.tsx` 클라이언트 컴포넌트):

1. `window.location.hash`가 `#/check`로 시작하면 `router.replace('/check' + location.search)` — 쿼리 유지.
2. `/check` 진입 시 `lib/utm.ts`가 `utm_*`를 `sessionStorage`에 저장(실패 시 무시).
3. 결과창 버튼은 `/consult?from=check&status=..&need=..`로 이동, 상담 폼은 저장된 `utm_*`를 숨김 칸으로 함께 제출.
4. 허용 목록 밖 `utm` 값·200자 초과 값은 버림.

## 7.5 폼 데이터 처리

**Supabase 권장 이유**: 접근 권한 정책(RLS), 암호화된 저장, 감사 기록, 국외 이전 고지 범위 명확. Google Sheet는 공유 실수로 개인정보·건강 관련 정보가 노출되기 쉬워 **이 폼에는 쓰지 않는다**(창업 문의처럼 건강 정보가 없는 폼도 1차는 같은 Supabase로 통일).

**표 설계**

```sql
-- consult_requests (빠른 간호 상담·대기등록)
id               uuid primary key default gen_random_uuid()
receipt_no       text unique not null          -- G-1023-0042
applicant_name   text not null
phone            text not null
dong             text not null                 -- 탄현동 | 중산동 | 덕이동 | 고봉동 | 성석동 | 기타:<입력>
care_status      text not null check (care_status in ('has_grade','pre_or_waiting','out_of_grade'))
needs            text[] not null               -- {'care','nursing','unsure'}
contact_time     text not null                 -- morning | afternoon | evening | any
memo             text                          -- 300자
from_check       boolean not null default false
utm              jsonb                         -- {source, medium, campaign, content}
consent_privacy  timestamptz not null
consent_health   timestamptz not null
consent_version  text not null
handling_status  text not null default 'new'   -- new | called | visited | contracted | closed
created_at       timestamptz not null default now()
purge_after      date not null                 -- 보관 기한(8.2절)

-- startup_inquiries (창업 문의) : 이름, 연락처, 희망 지역, 문의 내용, 동의 시각, 처리 상태, created_at, purge_after
```

- 저장은 **서버 액션에서 서비스 역할 키로만** 수행. 브라우저에 쓰기 키를 노출하지 않는다. 익명 사용자는 읽기·쓰기 권한 없음(RLS 전면 차단).
- 운영자 열람은 Supabase 계정(2단계 인증) 또는 2차 관리 화면.
- 보관 기한 지난 행은 매일 1회 삭제(Supabase 예약 작업 또는 서버 예약 실행).
- 로그·오류 추적 도구에 폼 본문을 남기지 않는다(접수번호만).

## 7.6 배포 전 자동 검사

- `rates/2025.json`의 모든 값이 `verified: true`이고 `sourceUrl`·`checkedAt`가 비어 있지 않아야 **운영 배포 통과**. 아니면 빌드 경고 + 결과창 숫자 숨김(F-05).
- 사이트 전체 텍스트에서 "이동목욕", "목욕차량" 문자열·차량 이미지 파일명 검사 → 있으면 실패.
- 화면 노출 문자열 검사: 메뉴·버튼·제목에 영문 단어가 있으면 경고(브랜드·단위 예외 목록 관리).
- 계산 단위 테스트: 경계값(한도 정확히 같음/1원 초과), 4가지 본인부담 구분, 두 계산기 결과 일치.
- 점수 단위 테스트: 각 등급 구간 경계 ±0.1점, 플래그 조합별 분기.

## 7.7 분석

- 개인 식별 없는 집계만: 페이지 조회, 자가진단 시작/완료, 결과→상담 버튼 클릭, 상담 제출 성공. 자가진단 **답변·결과 등급은 분석 도구로 보내지 않는다**.
- 도구: 네이버 애널리틱스 또는 쿠키 없는 방식(Q-WEB-11). 쿠키 사용 시 고지.

- **동의 분리**: ① 개인정보 수집·이용(필수) ② 건강 관련 정보(현재 상태·필요 서비스) 처리(필수, 별도 체크) ③ 마케팅 수신은 **받지 않음**(1차).
- 동의 문구에 수집 목적(상담·서비스 안내), 항목, 보관 기간, 동의 거부 권리와 불이익(상담 접수 불가, 전화 상담은 가능)을 적는다.
- **보관 기간**: 상담 종결 후 1년(안) — 운영자·법률 검토로 확정(Q-WEB-02). 계약으로 이어지면 센터 내부 시스템으로 옮기고 홈페이지 저장분은 삭제.
- 국외 저장(해외 클라우드 리전) 시 개인정보 처리방침에 국외 이전 고지. 가능하면 서울 리전.
- 개인정보 처리방침 페이지: 처리 목적, 항목, 보관 기간, 파기 절차, 위탁(호스팅·Supabase·알림 발송), 국외 이전, 정보주체 권리, 개인정보 보호책임자 연락처.
- 자가진단 답변은 수집하지 않으므로 방침에 "자가진단 응답은 저장·전송하지 않습니다"를 명시.

## 8.3 장기요양·광고 관련

- 결과창·계산기·비용 안내 페이지 모두 **"정확한 등급은 국민건강보험공단 판정 결과에 따름"** 과 "비용은 평일 낮 기준 예시" 문구 표시.
- **본인부담금 면제·할인, 금품 제공 등으로 수급자를 끌어들이는 광고 금지**(노인장기요양보험법상 유인·알선 금지 취지). "본인부담금 0원", "첫 달 무료" 같은 문구 금지. 법정 감경(9%·6%)·기초수급(0%) 안내는 제도 설명으로만.
- "등급 보장", "100% 등급 받게 해드림" 등 판정 결과를 약속하는 문구 금지.
- 등급 판정 전 간호에 대한 표현은 1.3절 주의 원칙을 따른다.
- 직원 실명·사진·자격은 본인 서면 동의 후 게시. 간호사 면허 보유 사실 표기는 사실 확인 후.
- 의료 행위 효과를 단정하는 표현(예: "욕창 완치") 금지. 의료광고 관련 규정 해당 여부 검토(Q-WEB-03).
- 창업 페이지: 수익 보장·확정 표현 금지, 법령 기준은 원문 링크로 안내.

## 8.4 보안

- HTTPS 전용, HSTS. 보안 헤더(CSP, X-Frame-Options 등) 설정.
- 서버 측 입력 검증(zod), 출력은 React 기본 이스케이프. `dangerouslySetInnerHTML`은 마크다운 렌더 시 허용 태그 목록으로만.
- 요청 빈도 제한: 같은 IP 1분 5회, 같은 연락처 10분 1회.
- Supabase 서비스 키는 서버 환경 변수에만. 저장소에 비밀값 금지.
- 운영자 계정 2단계 인증 필수, 퇴사자 계정 즉시 삭제.
